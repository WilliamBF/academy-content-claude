# Celonis Academy Content Style Guide

Pulled from three Confluence pages (Academy space, "Content Writing Best Practices" and its
children). These pages are the live source of truth  -  this file is a working copy for quick
reference. If a task seems to hinge on a detail not covered here, or the content looks like it
might have changed, re-fetch the live page instead of trusting this copy blindly:

- Content Writing Best Practices (landing page): https://celonis.atlassian.net/wiki/spaces/CA/pages/70944700/Content+Writing+Best+Practices
- Scripting Tips: https://celonis.atlassian.net/wiki/spaces/CA/pages/70943893/Scripting+Tips
- Different Perspectives in Our Training: https://celonis.atlassian.net/wiki/spaces/CA/pages/70942768/Different+Perspectives+in+Our+Training

## Scripting guidelines

- Write in an engaging, informal tone. ("Let's dive into how this works" not "This module will
  now proceed to explain...")
- Use active voice. ("Celonis triggers it automatically" not "It is automatically triggered by
  Celonis.")
- Address the learner with both "we" and "you" ("We can see that..." / "By clicking 'launch' you
  trigger the workflow...").
- Write learning objectives as outcomes: "After completing this course, you'll be able to
  configure a dashboard"  -  not "You will learn how to configure a dashboard."
- Start broad, then break the topic down step by step.
- Explain the theory, then ground it with a concrete example  -  ideally a real Celonis
  View/Skill/Objective.
- Use examples that carry business relevance, and include different possible use cases for a
  feature.
- Within a chapter, open each video with a short recap of what came before, and close with a
  short note on what's coming next.
- Write numbers as digits, except "one" (e.g. "3 key benefits", "There is one exception...").
- Keep sentences short. ("Click the button. You'll see a popup." not "After clicking the button,
  a popup will appear which includes further options that you may choose from depending on your
  goals.")
- Minimize connecting/filler phrases. ("Next, open the View." not "And now, we are going to go
  ahead and open up the View so that we can...")
- If the script will be turned into a voiceover, spell out code/special characters so the
  voiceover tool reads them correctly (e.g. "open-parenthesis, user ID, close-parenthesis" not
  "(user ID)").
- Voiceover scripts need shorter sentences than text meant to be read  -  working memory for audio
  is more limited. ("Select the KPI. Then click 'Save'." not "After selecting the KPI and
  considering the available options, proceed to click Save.")
- Plan the visuals alongside the script: note where a screen recording vs. a slide is needed, and
  draft initial slide content.
- When referring to Celonis training in the plural, always say "training," never "trainings."
- Be consistent with existing terminology and capitalization (see Naming Conventions below).
- Capitalize headlines correctly: capitalize the first letter of the first word only (sentence
  case), e.g. "Understanding the Process Explorer"  -  not "Understanding The Process Explorer" and
  not all-lowercase.
- Stick to the Celonis glossary (celonis.com/glossary) for terminology.
- Read the script out loud before finalizing  -  check it flows and is easy to follow.

## Script review process

Three review rounds (not all always needed):

1. Team-internal review.
2. Native-speaker review.
3. Academy review  -  only if warranted by necessity/capacity.

## Naming conventions

| Guideline | Don't | Do |
|---|---|---|
| Proper names (products, Touchpoints) are capitalized, both words if two-word. | academy, Insight explorer | Academy, Insight Explorer |
| Titles: capitalize first letter of each word except prepositions. | More To Explore, Choose your role | More to Explore, Choose Your Role |
| Drop-down/description text: only first letter capitalized, except proper nouns. | View all the knowledge in the celonis confluence space | View all the knowledge in the Celonis Confluence space |
| The Celonis logo is always lowercase "c"; the company name Celonis is capitalized. |  -  |  -  |
| Acronyms: spell out in full on first mention, acronym in parentheses; acronym alone after that. Common non-Celonis acronyms (AI, SQL) can stay as acronyms. Menu labels: use the acronym with a tooltip for the full term. | Object-centric process mining | Object-Centric Process Mining (OCPM) |
| Learner actions are written as: Log In / Sign Up, Log Out, Search (magnifying glass icon), Edit Profile, Admin & Settings. (Still fine as a noun, e.g. "the Login screen.") | Login, Logout, Search for content, Admin and settings | Log In, Log Out, Search (magnifying glass icon), Admin & Settings |
| Never use "EMS" (any case)  -  always "Celonis" or "Celonis Platform." | ems, EMS | Celonis Platform |
| Touchpoints (Academy, Trust Center, Marketplace, Support Center, etc.) are referred to as "Celonis + Touchpoint name" in web body text  -  except in menus/footers, or after the first mention in a paragraph, where "Celonis" is dropped. | Academy (in body text, first mention) | Celonis Academy |

## Inclusion in training content

From "Different Perspectives in Our Training"  -  treat this as a checklist while drafting
examples, characters, and visuals, not just a final pass:

**Inclusive and representative examples**
- Avoid stereotypes  -  let roles in examples reflect the full range of real people, not
  conventional assumptions.
- Use names from a variety of cultural backgrounds.
- Include people with disabilities in professional and leadership roles.
- Draw examples from varied industries, cultural contexts, and professional levels.

**Inclusive language**
- Use gender-neutral role terms ("team member," "leader") instead of gendered ones ("chairman,"
  "salesman").
- If using personal pronouns, balance them (he/she/they) or use gender-neutral phrasing.
- Avoid idioms or slang that may not translate across cultures.

**Visual representation**
- Use imagery spanning a range of ages, ethnicities, genders, abilities, and body types.
- Write alt text that reflects the same inclusiveness.
- Weave inclusion throughout the content, not as a one-off token example in a single section.

The underlying goal: every learner should feel seen, valued, and respected by the content  -  this
is a quality bar, not a checkbox exercise.
